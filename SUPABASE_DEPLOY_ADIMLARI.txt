--- 3a) analyze-signals ---

  curl -X POST "https://<PROJE_REF>.supabase.co/functions/v1/analyze-signals" \
    -H "Authorization: Bearer <ANALYZE_SIGNALS_CRON_SECRET>" \
    -H "Content-Type: application/json" \
    -d '{"dry_run":true}'

BEKLENEN yanıt alanları:

  "closed_or_deleted_lots": N   ← EN ÖNEMLİSİ.
        Satış ya da silme yüzünden elenen alım lot'u sayısı.
        N > 0 ise düzeltme fiilen çalışıyor demektir.
        N = 0 ise ya hiç satılmış/silinmiş lot'un yok ya da deploy
        gitmemiş — bu durumda bana yanıtın tamamını gönder.

  "preview": [...]              ← Bu turda bildirim gidecek varlıklar.
        AVOD ve AGHOL bu listede GÖRÜNMEMELİ. Görünüyorsa o lot'lar
        sunucuda hâlâ aktif; aşağıdaki "TEŞHİS" bölümüne bak.

  "assets" / "positions"        ← analiz edilen varlık/pozisyon sayısı
  "skipped_by_frequency"        ← sıklık penceresi yüzünden atlananlar
  "skipped_by_dedup"            ← aynı sinyal tekrar bildirilmediği için

PowerShell kullanıyorsan curl yerine:

  Invoke-RestMethod -Method Post `
    -Uri "https://<PROJE_REF>.supabase.co/functions/v1/analyze-signals" `
    -Headers @{ Authorization = "Bearer <ANALYZE_SIGNALS_CRON_SECRET>" } `
    -ContentType "application/json" `
    -Body '{"dry_run":true}' | ConvertTo-Json -Depth 6

--- 3b) daily-brief ---

  curl -X POST "https://<PROJE_REF>.supabase.co/functions/v1/daily-brief" \
    -H "Authorization: Bearer <DAILY_BRIEF_CRON_SECRET>" \
    -H "Content-Type: application/json" \

BEKLENEN: "ok": true ve "dry_run": true.

═══════════════════════════════════════════════════════════════════════
 TEŞHİS — "preview"de hâlâ AVOD/AGHOL görünüyorsa
═══════════════════════════════════════════════════════════════════════

O lot'lar sunucuda hâlâ AKTİF demektir. Dashboard → SQL Editor'da
kendi kullanıcı kimliğinle çalıştır:

  select id, ticker, kind, quantity, added_date, deleted_at, ref_asset_id
    from public.assets
   where user_id = auth.uid()
     and upper(ticker) like 'AVOD%'
   order by added_date;

Okuma kılavuzu:
  · deleted_at DOLU  → sunucu zaten eliyor, sorun push değil başka yerde
  · deleted_at BOŞ + kind='buy' + net miktar > 0
        → sunucuya göre bu varlık HÂLÂ SENİN. Uygulamada silme/satış
          işlemi sunucuya ULAŞMAMIŞ demektir.
  · kind='delete_log' satırı VAR ama alım lot'unun deleted_at'i BOŞ
        → tam olarak yakaladığımız yarım kalmış silme. Yeni sürüm bunu
          hem sunucuda susturuyor (mezar taşını dinliyor) hem de
          istemcide artık sessizce başarısız olmuyor.

Elle temizlemek istersen (DİKKAT: geri alınamaz, önce yukarıdaki
select ile ne sildiğini gör):

  update public.assets
     set deleted_at = now()
   where user_id = auth.uid()
     and upper(ticker) in ('AVOD','AVOD.IS','AGHOL','AGHOL.IS')
     and deleted_at is null;

Sonra ADIM 3a'yı tekrar koş; preview temizlenmiş olmalı.
